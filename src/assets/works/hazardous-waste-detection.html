01

Introduction

Scrap yards process thousands of mixed metal parts a day. A few of those parts are dangerous to crush, shred or cut: pressurised gas cylinders can explode, and shock absorbers carry hydraulic oil that has to be drained before recycling.

This project is an end-to-end computer vision system that spots those two items automatically. It covers the full machine learning lifecycle: dataset validation, class balancing, transfer-learning a YOLOv8 model, evaluation, and deployment as a REST API with a web front end, all packaged in Docker and driven from a single command-line entry point.

02

Problem Statement

Hazardous items are currently identified by workers looking at piles of scrap. That is slow, inconsistent across shifts, and puts people close to the very objects that are dangerous. The visual task is also hard: the items are rusted, partially buried, oddly lit and surrounded by look-alike metal parts.

Class 0

Cylinders

May hold LPG, CNG or refrigerant under pressure. Explosion risk if crushed or cut.

9
Class 1

Shock Absorbers

Contain hydraulic oil that is toxic and must be drained before recycling.

Goal: given a photo or camera frame from a scrap yard, locate every cylinder and shock absorber, label it, and return counts that can drive safety alerts or sorting decisions.

03

Proposed Solution

A single-stage object detector is a good fit: it looks at the whole image once and returns boxes, classes and confidence scores fast enough for live camera feeds. I fine-tuned YOLOv8 nano, starting from COCO-pretrained weights, so the model already knew general shapes and edges and only had to learn the two hazard classes.

  • Data layer: polygon-annotated images from Roboflow, validated and rebalanced with targeted augmentation.
  • Model layer: YOLOv8n trained with early stopping, evaluated with mAP, precision, recall and confusion matrices.
  • Serving layer: FastAPI loads the model once and answers image requests with JSON detections plus an annotated image.
  • Interface layer: a lightweight HTML/JS page for drag-and-drop uploads and webcam capture.
04

System Architecture

The project is split into a training pipeline that produces best.pt, and a deployment pipeline that serves it. One config.yaml drives both, so nothing is hard-coded.

05

Technical Breakdown

The codebase is modular: each stage is its own class, and main.py orchestrates them through a --step flag.

ModuleResponsibility
data_preparation.pyPairs images with labels, checks class IDs and coordinate ranges, splits 80/10/10, writes data.yaml.
balance_data.pyCounts objects per class, plans how many augmented copies each minority image needs, then generates them with label-aware transforms.
train.pyLoads COCO-pretrained YOLOv8n, trains with early stopping (patience 10), copies the best checkpoint to outputs/weights.
evaluate.pyComputes mAP@50, mAP@50–95, per-class precision/recall, plots curves and writes a text report.
inference.pyDetector class for single images, folders, video files and webcam streams; draws boxes and a count summary.
api/FastAPI app with Pydantic schemas, CORS, health and model-info endpoints, and a singleton model loader.

Training configuration

model:       yolov8n.pt  (COCO-pretrained)
image size:  640 × 640
epochs:      50 max, early stopping patience 10 → stopped at 39
batch:       16      optimizer: auto (SGD, lr0 0.01, momentum 0.937)
augment:     mosaic 1.0, HSV jitter, translate 0.1, scale 0.5, fliplr 0.5
inference:   conf 0.30, IoU (NMS) 0.45

Label-aware balancing

YOLO polygon labels are lists of (x, y) points, so a rotated or flipped image needs its points transformed in exactly the same way. The balancer passes polygons to Albumentations as keypoints, so geometry and labels stay in sync through flips, ±25° rotations, scaling, shifts, brightness and hue changes, blur and noise.

08

Engineering Challenges

Class imbalance

Shock absorbers outnumbered cylinders in the raw data, so the model risked learning to favour the majority class.

Fix: a balancing step that oversamples the minority class with augmentation. It prefers images that contain only cylinders, because augmenting mixed images would also inflate the majority class. The final split was 504 cylinders to 657 shock absorbers.

Keeping polygons aligned

Standard image augmentation rotates the pixels but not the annotation, which silently corrupts labels.

Fix: treating every polygon vertex as a keypoint so Albumentations transforms image and label together, then clipping and re-normalising points before writing YOLO format.

Cluttered, low-light scenes

Rust, shadows and overlapping metal make object boundaries hard to see.

Fix: photometric augmentation (brightness, contrast, hue, blur, noise) plus YOLO's mosaic augmentation so the model sees objects at many scales and in many contexts.

Training without a GPU

All training ran on a CPU.

Fix: the nano model variant, transfer learning from COCO weights and early stopping. Training finished in about 84 minutes and the final model is only 6 MB.

Slow model loading per request

Loading weights on every API call would add seconds of latency.

Fix: a singleton loader that reads the model once on first use and shares it across all requests.

Testing & Evaluation

The model was scored on the validation split after every epoch. Training stopped automatically at epoch 39 after ten epochs without improvement, and the weights from epoch 29 were kept.

0.995mAP@50
0.922mAP@50–95
0.956Precision
1.000Recall

The normalised confusion matrix showed every validation object assigned to its correct class, with no cylinder–shock absorber mix-ups and no missed objects.

10

Results & Learnings

The system works end to end: a user can drop a scrap-yard photo into the browser and get back labelled boxes and hazard counts. The model runs on a CPU without special hardware.

Reading the numbers carefully. The validation set is small (12 images) and its images come from the same source photos as some of the augmented training images. So the near-perfect scores show the pipeline learns the task, but they overstate how well it would do on a new yard. Building a held-out test set from different scenes is the most important next step.
  • Data work mattered more than model choice. Fixing imbalance and keeping labels correct through augmentation gave the biggest gains.
  • Splitting a dataset by source image, not by file, is essential when augmented copies exist; otherwise evaluation leaks.
  • Transfer learning makes small-data detection practical, even on a CPU.
  • Putting every setting in one config file made experiments repeatable and the codebase easy to hand over.
  • Serving ML is a software problem: validation, error handling, model lifecycle and containerisation take as much care as training.
11

Future Improvements

  • Collect more real scrap-yard images and evaluate on a scene-level held-out test set.
  • Add more hazard classes: batteries, fire extinguishers, airbag modules, fluorescent tubes.
  • Switch to YOLOv8 segmentation to use the polygon labels fully and estimate object size.
  • Export to ONNX or TensorRT for faster inference on edge devices beside conveyor belts.
  • Stream real-time video over WebSockets with object tracking, so each item is counted once.
  • Add alerting and a compliance log that records every hazardous item detected.
  • Train on a GPU with a larger variant (YOLOv8s/m) and compare accuracy against latency.
